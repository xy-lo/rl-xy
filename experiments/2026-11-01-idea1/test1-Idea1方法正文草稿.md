# Idea 1：面向晶圆级 GRPO 的 KV 局部性感知长尾协作

> **草稿状态。** 本文按“问题与动机—方法概览—布局与执行—联合调度—正确性与实验”的系统论文逻辑组织，描述的是拟议方法及本轮事件模型，不代表实体晶圆系统或真实 BF16 内核已实现。实验结论须以本轮审计结果为准；不得将未校准数字表述为硬件实测或已证实的论文优势。

## 1. 问题与动机

同步 GRPO 每个 prompt 生成多条回答，回答长度的差异使 rollout 尾部只剩少量长回答。已经完成的推理组不再参与本轮生成，但同步阶段仍需等待未完成回答。对于晶圆级架构，分布式 die 和片内 core 提供了可供重组的计算资源；不过，长回答已经积累的 KV 状态与 attention 权重具有明确的位置和容量占用。将计算扩展到空闲 die，必须同时处理历史 KV、后续新增 KV、跨 die 通信和输出同步。

因此，“增加 helper”带来的计算并行度，与维持 KV 访问局部性之间存在权衡。若不考虑状态位置，增加的 KV/权重传输及同步可能抵消计算收益；若只保持最初的静态放置，则无法利用已空闲的 die 分担长尾。本方法将**Q/KV 头组的数据布局与在线协作决策作为一个整体**，以同步 rollout 的完成时间为目标，在满足数据一致性、硬件容量与 GRPO 阶段依赖的前提下选择协作位置和介入时机。

此处有两种不同的“组”：GRPO 组指同一个 prompt 的多条回答；Q/KV 头组指一组共享同一 KV head 的 query heads。前者约束训练数据与奖励依赖，后者是 attention 计算及状态迁移的逻辑单元。

## 2. 方法概览

系统为每个 rollout TP 组维护活跃请求、已生成长度、KV 驻留和可用 die 的状态。prefill 后，各推理组按原 FIFO 规则 decode。当一个完整 TP 组空闲，控制器结合已完成请求的历史信息与当前可观察状态，评估继续本地执行、或将长尾组的部分 Q/KV 头及相关权重迁至空闲组。只在合法且预测净收益超过迁移与执行开销时启用协作；否则继续原执行。初始原型使用 TP4 源组与空闲 TP4 helper，在 attention 中组成 TP8，FFN 保持 TP4。

该方法的执行目标是缩短最后一条回答完成的时刻。在本轮分时共置模型下，生成完成后继续按同步阶段执行样本回传、old policy、reference、advantage、训练、optimizer 与发布；没有假设生成与训练并发。后续若引入提前训练，必须另外保证 GRPO 组内回答与奖励齐备、策略版本一致及全批次一次等效更新。

## 3. 面向协作的 Q/KV 布局

设模型有 $H_q$ 个 query heads 和 $H_{kv}$ 个 KV heads，每个 KV head 对应 $g=H_q/H_{kv}$ 个 query heads。我们以一个 KV head 与其对应的 $g$ 个 query heads 作为不可分割的逻辑归属单元。Qwen3-4B/8B 为 32/8，因此 $g=4$；14B 为 40/8，因此 $g=5$。头数必须能被所选 TP 均分，且每个 Q head 与其使用的 KV head 归属一致。

TP4→TP8 时，每条源 lane 的两个 KV head 分别归属于源 lane 和对应 helper lane；相应的 query heads、QKV 投影和输出投影分片跟随逻辑归属。每个 helper 接收所需的 attention 权重分片，以及活跃请求在该分片上已有的 KV 状态。对于不同请求，状态长度随当前上下文变化；事件记录保留请求身份和各自已处理长度，不能使用未来 EOS 决定迁移规模。

为避免把一个多 GB 的 KV 分片假设为单次驻留 SRAM，迁移按**有界缓冲流式打包/传输/解包**计价。当前事件模型以总字节估算额外打包和解包的读写服务，并显式建模源/目的端点和跨 die P2P；它不是实际 KV 页表、stride 或 DMA 描述符实现，缓存页碎片、真实打包吞吐和软件管理开销仍需进一步测量。

协作执行时，每个 TP8 lane 以本地 Q/KV 组计算 attention，随后以 8-rank 归约合并输出，源组继续 FFN。新生成 token 的 K/V 在拥有该 head 的源或 helper lane 写入；事件模型对这条持久化路径增加显式写入服务。该写入是相对于现有 QKV 输出的保守附加计费，可能与实际内核中的写出重叠或部分重复，不能视为硬件测量。租约结束时请求已完成，释放 helper KV 和租约；未完成时不得隐式丢弃或回滚状态，若未来支持中途回退，必须增加状态回收/同步协议。

## 4. 面向局部性的协作决策

控制器在完成事件与安全点检查可用组。对候选源 $i$ 与空闲 helper $j$，用已完成样本的条件历史和当前活跃请求的已生成长度估算剩余工作，用当前 KV 体积、权重分片和 6×9 mesh 路径估算迁移成本，并考虑每个后续 decode 步的 attention 本地计算、激活传输、归约及 KV 写入。初版候选评分可写为：

$$\widehat{G}_{ij}=\widehat{N}_{i}\bigl(\widehat{t}^{(4)}_{i}-\widehat{t}^{(8)}_{ij}\bigr)-\widehat{T}^{\mathrm{move}}_{ij},$$

其中 $\widehat{N}_{i}$ 是只由已观察信息得到的剩余步数估计，$\widehat{T}^{\mathrm{move}}_{ij}$ 包括权重与 KV 迁移及流式打包/解包的估算，$\widehat{t}^{(4)}$ 和 $\widehat{t}^{(8)}$ 分别表示相应执行方案的每步估算服务。控制器在合法资源和容量约束下比较候选源/helper，对预测收益未超过保守裕量的候选保持原执行；不得将正在服务其他任务的 die 当成空闲。

这是筛选启发式，并非完整的全局关键路径最优解。当前模型使用历史条件分位数和固定批形状预测，尚不能准确预测未来 batch 收缩、所有链路竞争或训练资源机会成本。原生网络按实际事件回放后给出模拟完成时刻；不可把预测收益当作最终收益，也不可把并行发生的迁移、计算和网络时长简单相加。

## 5. 一致性、容量与实验方法

每次候选必须检查：源/helper 互斥、模型和权重版本一致、头组完整且不重叠、状态位于正确 lane、DMA 临时缓冲及新的 KV 占用满足容量、归约成员与原计算语义匹配。每条请求应恰好完成一次，动态协作不能改变固定 trace 的 prompt、回答 token 工作量或完成条件；旧 KV 保留或释放的时间要与承诺的内存模型一致。已有小型 BF16 舍入输入/FP32 软件测试只能验证部分代数和状态归属，不能代替真实 BF16 权重与晶圆内核运行。

实验主表比较 GPU 分时共置 baseline、晶圆分时共置 baseline 和本联合方案；结果同时给出单步时间及有效 token 吞吐。每次 test1 回放使用对应模型 192 个 prompt、每个 8 条回答，共 1536 条轨迹；晶圆模型为 54 个物理 die、其中 48 个活动 die。4B/8B 的 rollout 使用 TP4，并发分别为 128/64；14B 原晶圆 baseline 使用 TP8/128，本方法为满足保守容量约束采用 TP4/64，需要在比较中明确此差异。端到端 step 使用 f2 的九个同步阶段，当前没有训练与生成重叠。

通信事件包含声明的权重和 KV 搬运、源/目标读写、附加流式打包/解包、逐层激活、8-rank 归约和声明的新增 KV 写入；控制器时间采用假定值。实际 packet/DMA setup、细粒度 NoC、真实 kernel 和 SRAM 生命周期尚未校准，故不能声称已经计全真实设备上的所有开销。原 GPU 是经部分 A100 算子测量校准后外推的 48 卡模型，晶圆是条件模型；二者都不是本轮实测集群。

## 6. 与现有方法的关系

GQA/KV 复用已有成熟 attention 工作，不能作为本文独创，例如 [FlashInfer](https://arxiv.org/abs/2501.01005)。[WSC-LLM](https://doi.org/10.1145/3695053.3731101) 已研究晶圆推理架构与资源、KV 管理；[WaferLLM](https://www.usenix.org/system/files/osdi25-he.pdf) 研究晶圆 core 级数据组织与 KV 管理；[TEMP](https://arxiv.org/abs/2512.14256) 和 [WATOS](https://arxiv.org/abs/2512.12279) 研究晶圆训练切分、通信与资源权衡；[RollPacker](https://www.usenix.org/conference/nsdi26/presentation/gao-wei) 研究同步 RL rollout 长尾及弹性资源。拟议差异是针对 GRPO 同步尾部，在给定晶圆 die/core 层级上把 Q/KV 分组的布局、状态迁移及空闲 die 的协作选择联合建模；是否形成足够新颖且有效的贡献，仍须更完整的相邻工作核对和公平实验验证。

## 7. 证据边界与论文写作占位

本稿方法段可用于讨论，但正式论文的收益表述必须等待本轮三档完整原生结果、输入/迁移/容量审计及 GPU/WSC 比较；若局部性方案相对合理对照没有稳定收益，应如实报告。test1 用于开发，独立窗口、真实或可信硬件成本标定和真实 Qwen/BF16 数值检查仍需完成；长度 trace 不包含真实采样/奖励，不提供学习质量结论。不要把历史 106→45 s 主要由 KV 访问假设改变造成的差额全部归为长尾调度。

### 本轮条件仿真结果（用于讨论，非最终论文结论）

在 4B/8B/14B 的 test1 中，本轮融合方案生成时间分别为 44.993/67.857/92.478 s；按已验证的八个非生成同步阶段组合后，完整 step 模型时间分别为 97.220/150.121/213.094 s。历史 GPU baseline 分别为 132.966/178.512/260.755 s，历史晶圆 baseline 为 159.060/208.238/266.747 s。三模型均为条件仿真，具体开销、二进制/切分差异及可信范围见 [实验结果与实现边界](三模型结果与实现边界.md)。

这些数据不能证明真实晶圆的加速，也不能将全部差异归因于动态协作：基线和方法的 KV 访问模型不同，14B 的 rollout 切分也不同；此外，真实 Qwen/BF16 kernel 和硬件未校准。论文中的实验结论需等独立窗口与模型验证完成后再定稿。
