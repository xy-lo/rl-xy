# 当前主实验：H0 54 die GRPO 与 Idea1

本实验采用 H0 / Case 3：6×9、54 个计算 die、每 die 256 core、64 GB DRAM，DRAM 与 D2D 模型参数均为 2 TB/s。54 die 组织为 9 个六 die 域，每域 3 个 TP2 副本；空闲 TP2 组可参与同域的 TP4 attention 协作。GPU 对照沿用 48 × A100 的 test1 模拟。

| 模型 | GPU baseline / s | H0 晶圆 baseline / s | 仅生成协作 / s | 完整 Idea1 / s |
|---|---:|---:|---:|---:|
| 4B | 132.966 | 162.372 | 107.623 | 108.836 |
| 8B | 178.512 | 245.501 | 187.004 | 186.396 |
| 14B | 260.755 | 348.756 | 285.635 | 276.267 |

每模型 192 prompt × 8 回答。仅生成协作是历史九阶段组合结果；完整 Idea1 在一个原生共享时钟中执行生成协作、提前准备/训练和最终更新。4B 完整方案比生成协作略慢，8B/14B 略有改善但仍慢于 GPU，不能预设所有模型获益。新实现、内存生命周期、完整复跑命令及压缩原生证据见 [Idea1 联合方案](IDEA1_JOINT.md)；原基线的详细参数与身份仍见 [原 H0 实验文档](../experiments/2026-11-02-h0-54/完整实验文档.md)和[原结构化结果](../experiments/2026-11-02-h0-54/results.json)。

早期 [Idea1 文档](IDEA1.md)及 48 活动 die 的结果保留为历史实验，不代表此 54 die 配置；Case 4 48 die 是另一个硬件候选。

## 源码与复现

`experiments/2026-11-02-h0-54/` 保留本次两套独立的源码补丁和实际 Idea1 调度源文件。为了保护仓库原 f2、48 die 历史入口，54 die 的公共引擎以可审核的补丁形式提供；4B/8B 和 14B 必须各使用自己的干净副本：

```bash
# 在本仓库根目录；使用各自的全新目录，保留原仓库不变。
git clone --local . /tmp/rlxy-h0-small
git clone --local . /tmp/rlxy-h0-14b
git -C /tmp/rlxy-h0-small apply "$PWD/experiments/2026-11-02-h0-54/h0-source.patch"
git -C /tmp/rlxy-h0-14b apply "$PWD/experiments/2026-11-02-h0-54/h0-14b-source.patch"
```

准备含本仓库提供的 sequence/RPC 扩展的 AstraSim：固定上游 revision 和完整补丁见 [原生后端说明](IDEA1.md#准备原生后端)。以下示例需要安装 `.[f2]`、protobuf 及原生构建依赖，并将 `ASTRA_SIM_ROOT` 设为实际原生源码目录，其中二进制位于 `build-dynarl/bin/AstraSim_Analytical_Congestion_Aware`：

```bash
export ASTRA_SIM_ROOT=/path/to/astra-sim
export ASTRA_SIM_BIN="$ASTRA_SIM_ROOT/build-dynarl/bin/AstraSim_Analytical_Congestion_Aware"
export H0_SCRIPTS="$PWD/experiments/2026-11-02-h0-54"
PYTHONPATH=/tmp/rlxy-h0-small/src python "$H0_SCRIPTS/replay_h0.py" --model 4B --platform wafer --window test1 --output /tmp/h0-output/4b-baseline
PYTHONPATH=/tmp/rlxy-h0-small/src:"$H0_SCRIPTS/idea" python "$H0_SCRIPTS/idea/locality_gqa_4b_v3.py" --mode ideal-gqa --model 4B --cap 32 --train-tp 2 --train-mb 4 --logprob-mb 8 --helper --priority --safe-points --interval 16 --window test1 --native-root "$ASTRA_SIM_ROOT" --cache-root /tmp/h0-output/4b-cache --output /tmp/h0-output/4b-idea
```

8B 使用 small 副本、`--train-mb 2 --logprob-mb 1 --cap 16`；14B 使用 14b 副本与 `idea-14b` 目录，`--train-mb 1 --logprob-mb 1 --cap 16`。静态 baseline 入口自动选取对应固定策略。为每次运行提供新的输出与缓存目录，并保存源、数据、配置和二进制哈希。当前发布重新整理了路径和实验入口；历史数字由各次实际 source/binary 身份产生，不能把新 Git 提交伪称为历史运行版本。本仓库提供摘要、结果和审计，完整原生事件日志保留在原实验工作区。

公开的原始结果副本将本机绝对路径替换为 `<historical-workspace>`；因此副本文件的哈希与 `results.json` 记录的原始运行文件哈希不同，后者保留原身份供追溯。原始完整事件日志与本机 bundle 未随仓库上传。
